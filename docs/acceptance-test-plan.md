# 第一版验收与测试计划

状态：第一版离线测试已开展，单条和批量 Actor 数据处理链路已真实运行成功；平台验收仍不完整。当前证据和限制见 [测试状态](test-status.md)。用合成 fixture 和模拟 MCP 验证确定性逻辑，并在获得授权后使用公开测试视频与用户自己的 Apify 账户进行真实测试。分别记录 Codex、ChatGPT 的日期、客户端/版本、Skill 版本、MCP/插件版本、账户套餐、工作区及角色、授权方式、Actor build/schema、测试输入授权、预期/实际、限制与缺陷；run ID 仅存于受保护测试记录，不记录 Token、Instagram 会话凭据或私人内容。测试前重新核实当前 schema 和限制。

## Skill、执行与数据

| 场景 | 可操作的验收标准 |
| --- | --- |
| 单条 | 对获授权的公开 URL 提交 `videoUrl`，实际 run 完成后将输出身份与输入核对，获得非空原文；有 segments 时仅显示实际时间戳，不要求所有视频都返回 segments。 |
| 批量、部分失败 | 模拟并实测多条 `bulkUrls`；对成功、失败、无有效文本、未返回和待核验分别输出清单和统计，run 成功不视为每项成功。 |
| 顺序与身份 | fixture 打乱 dataset 顺序；按 URL/shortcode 匹配，缺身份、多候选、冲突和重复输出保持未归属，不按顺序猜测。 |
| 重复与统计 | 验证设计中的 A、A、B、C、D 示例：5 行、4 请求；成功 1、失败 1、无有效 0、未返回 1、待核验终态 1；未归属 1 单列，无身份项不自动标记 C 身份冲突，A 回映两行。 |
| 字段组合 | 四种 text/errMsg 组合按设计互斥分类；两者非空保留文本及错误、列待核验；空白、缺字段、异常类型均有明确处理，不编造原因。 |
| 空 dataset | 成功 run 完整读取后未匹配请求为未返回；失败、终止或超时的 run 完整读取后标记 run 未成功并展示状态；运行中、状态未知或读取不完整为待定。 |
| run 登记与覆盖 | 每次实际启动后关联批次成员、run ID 和可得的 dataset ID；汇总前核对会话中所有已知 run。模拟缺失 ID、未知提交和不一致证据，受影响请求不能最终标为未返回；脚本无法发现完全未传入的 run 或证明宿主未截断。 |
| 失败 run 部分结果 | 对 FAILED、ABORTED 和 TIMED-OUT 模拟有可信文本及无匹配请求，保留文本并显示实际 run 状态；每个请求仅计入一个状态，不自动启动新 run。 |
| 同一 run | 模拟和实测等待超过初次调用：后续查询原 run ID；会话中断后验证可恢复能力。不得为继续等待重新启动。 |
| 响应丢失 | 模拟提交已发生但响应丢失，先查询或核对 Console；未能唯一确认则报告未知，断言没有自动第二次启动。 |
| 分页和截断 | 模拟多页、重复页、读取失败与截断；发现不完整时不声称结果完整；只重试读取，不启动 Actor。 |
| 批次证据覆盖 | 使用两个包含不同请求的批次，分别验证完整、缺失、重复 run/dataset、ID 不匹配、未启动、运行中、提交未知和分页不完整；仅成功且完整、绑定正确的批次可将未匹配项列为未返回；互斥统计并回映原始行。不得以 evidence 数量代替身份核对。 |
| 非法结果容器 | 字典信封、字符串、null 等非法 items 返回可机器读取错误，不能变成空 dataset；验证只有提取后的数组可用。 |
| 合规分批 | 模拟实际允许的每 run 限制：一个用户任务拆多个 run，每批关联输入和状态，不逐批确认；不规避账户限制。限制无法确定时提示而不臆造规则。 |
| 部分重试 | 按原始意图对已确认终态且可确定目标的失败项有限重试；未返回先核对，成功项不重跑，新旧 run 可追溯；未知提交状态不重发。 |
| 默认增强 | 模拟检查单条、多条以及合规新 run 的请求均显式 `enhancedcrawl: true`；经授权真实测试检查 Actor 接收的输入和可观察行为，有合适样本时进一步测试增强解析。不得以不同 run 结果完全相同作为唯一标准，也不保证增强成功。验证 run 内增强不会触发新 run。 |

## 用户体验

- 新用户安装、注册/登录自己的 Apify 账户并完成连接；首次简短提示可在 Console 查看 Runs 和计费明细及 Actor 页面。安装、连接和调用分别记录。
- 已授权用户再次使用时不重新配置；验证授权过期或撤销时能说明实际情况并引导重新连接。OAuth 不可用时只使用平台的安全凭据配置，不把秘密发往聊天、URL、仓库、日志或导出。
- 正常单条和批量请求不由产品反复提醒费用、估算或增加无谓确认；用户主动询问及额度不足时指向 Console。记录平台自身要求的审批，不绕过。
- 普通用户无需理解内部增强或 Instagram 会话字段；不承诺免费、增强必定成功或绝无重复计费。完整 transcript、摘要、翻译和推断有明确标签；无 transcript 时不编造摘要、人物、画面或时间戳。
- 当平台支持并实测后，分别验证 CSV/TXT 上传、列选择、编码、重复与无效行，以及 CSV/JSON/Markdown 导出；不支持时可粘贴链接和复制结果。未测功能不标支持。

## 平台独立发布门槛

四个独立结果必须分别记录：**Skill 安装/加载并触发、Apify 连接授权、Actor run 成功启动及查询、用户获得匹配的正确 transcript**。任何一个通过都不能推断其他项通过。

- **Codex**：从 GitHub 子目录安装到目标实际扫描目录，验证发现和显式/自然触发；单独验证 Apify 官方 MCP 或插件连接、OAuth、单条与批量调用、run 状态和 dataset 读取、失败和授权失效、文件能力及会话恢复。记录实际版本和限制。另观察工具 total 是否仅首页可用，以及同 shortcode 不同路径在 Actor 输出中的身份。
- **ChatGPT**：分别验证 Skill 上传/插件安装及发现触发、Apify 连接和 OAuth、可用工具、单条/批量 run、状态查询和 dataset 读取、失败和授权失效、文件能力及恢复。若被套餐、工作区、角色、管理员权限或具体环境阻断，记录页面/步骤、可见错误、版本和阻断原因；无法证明原因时标未知。此前连接受阻不算通过。
- 各平台只有真实验证通过后才可宣称对应能力兼容；ChatGPT 阻断不阻断 Codex 的开发和独立发布判断。Manus、OpenClaw、Cursor 不作为首版门槛，也不因其他平台通过而宣称兼容。

发布前回归模拟和该平台端到端测试，复核最新 Actor schema、官方文档及账户限制，更新兼容矩阵和未解决问题；不依赖未经授权的真实数据。
