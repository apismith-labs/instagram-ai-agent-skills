# Instagram Transcript Extractor：第一版详细设计

状态：第一版实现、离线测试及单条和批量真实数据处理测试已开展；尚未发布，平台兼容性尚未完整验证。项目是面向普通用户的 Instagram AI Agent Skills 集合，可扩展 Reels 分析、竞品监测、Creator 分析、评论与受众研究；一个业务 Skill 可组合多个 Actor。本次仅设计 `instagram-transcript-extractor`，使用 `apple_yang/instagram-transcripts-scraper`。当前证据见 [测试状态](test-status.md)，接口依据见 [接口核实记录](interface-verification.md)。

## 范围与结果

用户提供一条或多条公开视频、Reel 或支持的帖子 URL，要求获取 transcript 时触发。首版必须处理单条和批量；按用户要求给出原文、真实可用的 segments 时间戳、摘要、翻译或简单内容分析。明确区分原文和生成内容，区分可证实的信息与基于文本的推断；不编造对白、人物、画面或时间戳。没有有效 transcript 时不生成基于它的摘要或翻译。语音识别可能有误，必要时标注不确定性。

CSV/TXT 输入及 CSV/JSON/Markdown 导出为条件支持，只有目标宿主实际可读写并通过测试时才声明；否则用户粘贴链接、复制结果。定时监控、字幕文件、个人主页采集及其他业务 Skill 后续处理。

## 请求、匹配与状态

1. 保留每个输入行号和原始 URL，校验公开 Instagram URL；报告无效行。可安全确认相同路径和 shortcode 的 URL 变体仅提交一次，结果回映射至所有原始行。身份规范化用于去重与比对：主机大小写、www/非 www、尾斜杠、已知跟踪参数及片段可安全处理，shortcode 保持大小写；每行原始 URL 保留，首次 URL 供提交。未知参数和特殊链接不猜测，提示重新复制。不同路径同 shortcode 先视为候选重复，未经验证不自动合并；无法确定身份的输入保持独立。报告有效输入行数、无效行数及唯一请求数。
2. 单条用 `videoUrl`，多条用 `bulkUrls` 字符串数组；不填个人主页模式。内部显式传 `enhancedcrawl: true`，使产品默认策略不依赖 schema prefill 或 Actor 缺省行为。增强解析是 Actor 在**同一个 run 内**的处理；重新启动 Actor 是新 run，两者不同，普通用户无需选择或理解内部参数。验证请求、Actor 收到的输入和可观察行为；无需额外用户确认，亦不承诺解析必然成功。
3. 按已知且适用的 Actor 每 run 限制及 Apify 套餐、权限、客户端大小和时长限制规划。若规则允许，可将一个用户任务拆成多个合规 run，逐批保留输入清单、run ID、dataset ID 和状态，正常分批不逐批询问。不能利用分批规避明确的账户、套餐或使用限制；不能确认规则时不要假设允许。大量任务需要实际验证限制，不预设未经证实的硬上限。
4. 一次启动后记录 run ID 和 dataset ID，查询同一 run，非终态有界退避；等待超时说明仍在执行并保留继续查询入口。若提交响应不明，先查可用的运行列表或 Console，根据 Actor、时间和可用输入信息核对；无法唯一确认则报告状态未知，不自动启动新 run。宿主无法恢复时记录限制。状态、输入和结果只在获得授权的可用存储内保存必要信息，避免泄露。不能保证绝无重复运行或计费。
5. 终态后分页读取 dataset，检查结果计数、页边界、截断或读取异常；读取可以安全重试，未读全时不作最终未返回结论。run 失败或超时仍检查可取得的部分结果；run 成功不等于每条成功。使用输出 `url` 的可靠规范化身份和 `code` 匹配，`pk`/`id` 仅在已有确定映射时辅助；绝不按 dataset 顺序配对。无身份、多候选、身份冲突及重复输出保留并标记待核验，禁止猜测；单条可确认结果与冲突并存时保留其文本，重复结果作为候选展示。

每个**唯一请求**仅归一个互斥终态；以去除首尾空白后的非空文本判断：

| 匹配结果 | 终态 | 处理 |
| --- | --- | --- |
| text 非空，errMsg 空或缺失 | 成功 | 保留原文与可用 segments |
| text 空或缺失，errMsg 非空 | 失败 | 保留实际错误，不猜原因 |
| text 空或缺失，errMsg 空或缺失 | 无有效 transcript | 原因待核验 |
| text 非空，errMsg 非空 | 待核验 | 保留文本和错误/警告，不能判定完全成功或失败 |
| 成功 run 的 dataset 完整读取后无对应或冲突候选 | 未返回 | 列出请求；有身份冲突或重复候选时归入待核验并展示候选 |
| 失败、终止或超时 run 的 dataset 完整读取后无对应或冲突候选 | run 未成功 | 列出实际 run 状态；不隐藏失败 |
| 状态未知或 dataset 未完整读取 | 待定 | 已匹配结果标记暂定 |

`待核验`终态包括内容与错误并存、身份冲突或重复候选；已确认的文本仍需展示。身份歧义标记是跨状态的标记，**不再加到互斥状态总数**；无身份结果作为未归属输出单独计数，不能算作某个输入的成功或失败。输出类型异常或冲突也保留原始数据并标记待核验；在未完成、未读全或身份不确定时，清楚说明统计为暂定。

**统计示例**：有效输入行依次为 A、A、B、C、D，共 5 行，去重后 4 个请求。dataset 无序返回：D 有文本且有错误；A 有文本且无错误；一项无身份结果；B 有错误且无文本；C 无可唯一对应结果。最终成功 1（A）、失败 1（B）、无有效 transcript 0、未返回 1（C）、待核验终态 1（D），合计 4；另有未归属结果 1，无身份项不自动给 C 添加身份冲突标记。A 的结果回映两行；不可把无身份结果指定给 C。无效输入若有，另报数量，不加入唯一请求的终态总数。

明确终态后的部分失败，可依据用户已表达的任务意图有限重试确定的失败项，必要时重试经核对的未返回项；记录新 run 与原 run 的关联，不重跑成功项。读取或提交状态不明时先恢复和核对，不自动重发。用户要求重试时遵循其范围；不可确定候选时先说明并取得必要信息。额度不足、权限问题或授权失效时给出相应修复入口。

## 文件与用户流程

有文件能力时 CSV 保留行号、处理表头和引号；有多个可能 URL 列时询问用户，TXT 按行读取；无效行单列。导出按原始行映射，包含状态、来源、可用原文与错误；JSON 保留结构，CSV 防范公式注入，Markdown 适合阅读。不要将 Token、会话凭据或用户私有文件写入仓库、日志或导出。

- 新用户安装 Skill，注册或登录自己的 Apify 账户，在平台原生连接界面授权，粘贴链接。首次可简短指向 Apify Console 的 Runs 和计费明细及 Actor 页面。
- 已有账户但未连接：单独连接 Apify 并授权；安装和授权是不同步骤。已连接的用户后续直接提出任务，授权失效或撤销时重新连接。
- 优先官方 MCP/插件和 OAuth；OAuth 不可用时仅使用宿主提供的安全凭据配置。没有安全入口则说明阻断，不要求用户在聊天粘贴凭据。普通用户无需理解内部增强参数或 Instagram 会话字段。
- 普通任务不反复提示费用、估算或增加确认；用户询问费用、账户额度不足时指向自己的 Console。宿主本身的操作审批照其规则执行，不绕过。面向用户的 Skill、README、指南不写具体金额、费率、生效日期或估算，也不承诺免费或不会重复计费。

Codex：将 GitHub 的 Skill 子目录通过 `$skill-installer` 安装到目标环境实际扫描的用户 Skill 目录，或用正式插件分发；仓库 `skills/` 本身不等同扫描位置。安装后新会话检查发现、显式调用及自然触发；单独连接 Apify OAuth，并验证实际工具。以目标安装器和 Codex 版本确定准确位置，不假设所有环境一致。

ChatGPT：先验证账户是否可上传 Skill 或安装适用插件，并验证实际发现和触发；分别验证官方 Apify 插件/自定义 MCP 的可用入口、工作区权限、OAuth 和 Actor 操作。提示词示例不是正式安装；MCP 连接也不是 Skill 安装。工作区、角色、套餐或界面阻断须记录具体信息；只阻断 ChatGPT 兼容声明，不阻断 Codex 路径。两个平台分别记录版本、日期、权限、安装、授权、run、结果及文件能力。Manus、OpenClaw、Cursor 后续扩展，不作为首版验收门槛。

未来发布时计划采用版本标签和变更记录；README 只标已实测能力，未测标待验证。各 Skill 独立发行单元，可共享版本化参考资料，未来再确定插件包装和渠道；不将最终发行渠道选择作为当前开发阻断。
